Stream Library — Usage Guide

Interactive examples showing how to use the stream library. Every example runs in your browser using the in-memory transport — no server needed. Click Run to see results.

Source: shared/lib/stream/ — PR #254

1. Quick start

Create a stream, publish a message, subscribe to it. createStream is the main entry point — give it a name and buffer capacity. 

// Create a stream with a 100-message ring buffer
const stream = createStream({ name: 'demo', bufferCapacity: 100 });

// Subscribe — handler receives envelopes (payload + metadata)
const unsub = stream.on((envelope) => {
  log('Received:', envelope.payload);
  log('  seq=' + envelope.seq + ', from=' + envelope.from);
});

// Publish a message
stream.append({ greeting: 'hello, stream library' });

// Publish another
stream.append({ greeting: 'messages are typed and sequenced' });

// Unsubscribe
unsub();
stream.append({ greeting: 'this one is not received (unsubscribed)' });

log('---');
log('Buffer has', stream.latest(10).length, 'messages total');
createStream + on + append

2. Result types

Every fallible operation returns Result<T, E> instead of throwing. This makes error handling explicit — you always know whether something succeeded by checking .ok, and you can chain operations with map and flatMap. 

// Create success and failure values
const good = ok(42);
const bad = err(new Error('something broke'));

log('good.ok =', good.ok, '  good.value =', good.value);
log('bad.ok =', bad.ok, '   bad.error =', bad.error.message);

// map — transform the success value
const doubled = map(good, (n) => n * 2);
log('map(good, x2) =', doubled.value);

// map on an error passes through unchanged
const stillBad = map(bad, (n) => n * 2);
log('map(bad, x2).ok =', stillBad.ok);

// flatMap — chain fallible operations
const parsed = flatMap(ok('{"x":1}'), (s) => {
  try { return ok(JSON.parse(s)); }
  catch (e) { return err(e); }
});
log('flatMap parse:', parsed.value);

const parseFail = flatMap(ok('not json{'), (s) => {
  try { return ok(JSON.parse(s)); }
  catch (e) { return err(e); }
});
log('flatMap bad parse:', parseFail.ok, '-', parseFail.error.message);

// unwrapOr — extract value with a fallback
log('unwrapOr(good, 0) =', unwrapOr(good, 0));
log('unwrapOr(bad, 0) =', unwrapOr(bad, 0));
ok / err / map / flatMap / unwrapOr

Why not throw? The existing codebase has scattered try/catch blocks around JSON parsing, WebSocket ops, and encoding. Result types make failure handling explicit and composable. A failed parse looks the same as a successful one — no invisible control flow jumps.

3. Transports

A Transport is an abstract bidirectional message pipe. The library ships three implementations: WebSocket, HTTP poll, and in-memory. They all implement the same interface, so you can swap transports without changing application code.

The memory transport creates two linked ends — anything sent by the client arrives at the server, and vice versa. This is what makes the examples on this page work without a real server. 

// Create a linked client/server pair
const { client, server } = createMemoryTransport();

// Register handlers before opening
const serverMessages = [];
server.onMessage((data) => {
  serverMessages.push(data);
  log('Server received:', data);
  // Echo back with a prefix
  server.send('echo: ' + data);
});

const clientMessages = [];
client.onMessage((data) => {
  clientMessages.push(data);
  log('Client received:', data);
});

// Open both ends
await client.open();
await server.open();

log('Client state:', client.state);
log('Server state:', server.state);

// Client sends to server
client.send('hello from client');
client.send('another message');

log('---');
log('Server got', serverMessages.length, 'messages');
log('Client got', clientMessages.length, 'echo replies');

// Close
client.close();
log('Client state after close:', client.state);
createMemoryTransport — client/server pair

Binary data over transport

Transports handle both strings and Uint8Array binary data. Audio frames, for example, travel as binary. 

const { client, server } = createMemoryTransport();

server.onMessage((data) => {
  if (data instanceof Uint8Array) {
    log('Server received binary:', data.length, 'bytes →', Array.from(data));
  } else {
    log('Server received string:', data);
  }
});

await client.open();
await server.open();

// Send a JSON control message
client.send('{"type":"speech_start"}');

// Send binary audio frames
client.send(new Uint8Array([0x01, 0x02, 0x03, 0x04]));
client.send(new Uint8Array([0x05, 0x06, 0x07, 0x08]));

// Send another JSON control message
client.send('{"type":"speech_end"}');
Mixed string + binary on one transport

4. Streams and subscriptions

A Stream wraps a ring buffer with pub/sub. Every message appended gets a monotonic sequence number and timestamp, then is delivered to all subscribers and stored in the buffer for replay. 

const stream = createStream({ name: 'events', bufferCapacity: 100 });

// Subscribe to live messages
const received = [];
stream.on((env) => received.push(env));

// Append several messages
for (let i = 0; i < 5; i++) {
  stream.append({ type: 'tick', value: i });
}

log('Received', received.length, 'live messages');
log('Sequence numbers:', received.map(e => e.seq).join(', '));

// Query the buffer: latest(n)
const last3 = stream.latest(3);
log('---');
log('latest(3):');
last3.forEach(e => log('  seq=' + e.seq, JSON.stringify(e.payload)));

// Query the buffer: since(seq) — everything after seq 2
const afterSeq2 = stream.since(createSequenceNumber(2));
log('---');
log('since(seq=2):');
afterSeq2.forEach(e => log('  seq=' + e.seq, JSON.stringify(e.payload)));
subscribe, query with latest() and since()

Ring buffer overflow

When the buffer is full, oldest messages are silently evicted. This is the expected behavior for bounded streams. 

// Tiny buffer: capacity 5
const stream = createStream({ name: 'tiny', bufferCapacity: 5 });

// Append 10 messages
for (let i = 0; i < 10; i++) {
  stream.append({ n: i });
}

// Buffer only holds the last 5
const all = stream.latest(100);
log('Buffer size:', all.length, '(capacity 5)');
log('Kept messages:');
all.forEach(e => log('  seq=' + e.seq, '→ n=' + e.payload.n));
log('---');
log('Messages 0-4 were evicted to make room for 5-9.');
Ring buffer eviction

5. Dedup (compositional)

Deduplication is not built into streams. Instead, createDeduplicatedStream wraps any stream with a dedup filter. You provide a key function that extracts the dedup key from each message.

This compositional approach means you choose: plain stream (no overhead) or deduplicated stream (when duplicates are possible, e.g. chat messages re-sent on reconnect). 

// Plain stream — no dedup
const inner = createStream({ name: 'chat', bufferCapacity: 100 });

// Wrap with dedup — key function extracts message ID
const dedup = createDedup();
const stream = createDeduplicatedStream(
  inner,
  dedup,
  (msg) => msg.id,  // deduplicate by message ID
);

const received = [];
stream.on((env) => received.push(env.payload));

// Send three messages, two with the same ID
stream.append({ id: 'msg-1', text: 'hello' });
stream.append({ id: 'msg-2', text: 'world' });
stream.append({ id: 'msg-1', text: 'hello (duplicate)' });  // duplicate!
stream.append({ id: 'msg-3', text: 'third' });

log('Sent 4 messages, received', received.length, '(1 duplicate filtered)');
received.forEach(m => log('  ' + m.id + ': ' + m.text));
createDeduplicatedStream — compositional dedup

Timed cache for TTL-based dedup

By default, dedup remembers keys forever. Use createTimedCache as the backing store to expire keys after a TTL. This is useful for chat dedup where a message re-sent after 5 seconds is probably intentional. 

// Create a timed cache with controllable clock
let now = 0;
const cache = createTimedCache({
  ttlMs: 5000,
  now: () => now,
});
const dedup = createDedup(cache);

// First check — not a duplicate
log('msg-1 duplicate?', dedup.isDuplicate('msg-1'));

// Same key immediately — duplicate
log('msg-1 duplicate?', dedup.isDuplicate('msg-1'));

// Advance time past TTL
now = 6000;
log('(time advances 6 seconds)');

// Same key after TTL — no longer duplicate
log('msg-1 duplicate?', dedup.isDuplicate('msg-1'));
createTimedCache — TTL-expiring key store

6. Channels — routing and identity

A Channel adds sender/receiver addressing on top of a stream. Each channel has an identity (the sender name). Messages can be targeted (to a specific recipient) or broadcast (to everyone).

6.1 Peer-to-peer messaging

// Shared stream for the "work" channel
const stream = createStream({ name: 'work', bufferCapacity: 200 });

// Two participants with different identities
const supervisor = createChannel('work', stream, 'supervisor');
const porter = createChannel('work', stream, 'porter');

// Each participant logs messages addressed to them
porter.on('porter', (env) => {
  log('[porter received]', JSON.stringify(env.payload.payload));
});
supervisor.on('supervisor', (env) => {
  log('[supervisor received]', JSON.stringify(env.payload.payload));
});

// Supervisor sends a task to porter
supervisor.send('porter', { task: 'build the widget' });

// Porter replies to supervisor
porter.send('supervisor', { reply: 'widget complete' });
Targeted peer-to-peer messaging between two participants

6.2 Broadcast to multiple participants

// Three participants on the same stream
const stream = createStream({ name: 'announcements', bufferCapacity: 200 });

const supervisor = createChannel('announcements', stream, 'supervisor');
const porter = createChannel('announcements', stream, 'porter');
const atlas = createChannel('announcements', stream, 'atlas');

// All three listen for broadcasts
supervisor.onBroadcast((env) => {
  log('[supervisor heard]', JSON.stringify(env.payload.payload));
});
porter.onBroadcast((env) => {
  log('[porter heard]', JSON.stringify(env.payload.payload));
});
atlas.onBroadcast((env) => {
  log('[atlas heard]', JSON.stringify(env.payload.payload));
});

// Supervisor broadcasts — porter and atlas both receive it
supervisor.broadcast({ alert: 'deploy starting in 5 minutes' });

// Porter broadcasts — supervisor and atlas both receive it
porter.broadcast({ status: 'build complete' });
Broadcast messages reach all three participants

6.3 Filter by sender

// Supervisor monitors what porter says, ignoring others
const stream = createStream({ name: 'chatter', bufferCapacity: 200 });

const supervisor = createChannel('chatter', stream, 'supervisor');
const porter = createChannel('chatter', stream, 'porter');
const atlas = createChannel('chatter', stream, 'atlas');

// Supervisor only listens to porter's messages
supervisor.from('porter', (env) => {
  log('[from porter]', JSON.stringify(env.payload.payload));
});

// Porter sends — supervisor sees this
porter.broadcast({ note: 'widget deployed' });

// Atlas sends — supervisor does NOT see this
atlas.broadcast({ note: 'index rebuilt' });

// Porter sends again — supervisor sees this too
porter.send('supervisor', { note: 'all clear' });
Filter to only see messages from a specific sender

7. Codecs

Codecs handle serialization with typed errors. createJsonCodec returns Result values instead of throwing on malformed input. The optional validator parameter adds schema checking. 

// Basic JSON codec — no schema validation
const codec = createJsonCodec();

// Encode an object to a JSON string
const input = { type: 'chat.message', text: 'hello' };
const encoded = codec.encode(input);
log('encode(', JSON.stringify(input), ') →', encoded.ok ? encoded.value : 'ERROR');

// Decode valid JSON back to an object
const validJson = '{"type":"chat.message","text":"hello"}';
const decoded = codec.decode(validJson);
log('decode(', validJson, ') → ok?', decoded.ok, '→', JSON.stringify(decoded.value));

// Decode invalid JSON — returns err, never throws
const malformed = 'not valid json{{{';
const bad = codec.decode(malformed);
log('decode(', malformed, ') → ok?', bad.ok, '— error:', bad.error.message);
createJsonCodec — safe encode/decode

Validator integration

Pass a validator function to createJsonCodec to reject structurally valid JSON that doesn't match your schema. 

// Validator: must have "type" and "text" string fields
function isChatMessage(v) {
  return v !== null
    && typeof v === 'object'
    && typeof v.type === 'string'
    && typeof v.text === 'string';
}

const codec = createJsonCodec(isChatMessage);

// 1. Valid message — passes both JSON parse and validator
const validInput = '{"type":"chat.message","text":"hi"}';
const good = codec.decode(validInput);
log('decode(', validInput, ')');
log('  → ok?', good.ok, '— value:', JSON.stringify(good.value));

// 2. Valid JSON, wrong schema — parsed fine, but validator rejects it
const wrongInput = '{"count":42}';
const wrong = codec.decode(wrongInput);
log('decode(', wrongInput, ')');
log('  → ok?', wrong.ok, '— error type:', wrong.error.constructor.name, '— SchemaError, not DecodeError');

// 3. Invalid JSON — can't even parse
const brokenInput = '{{{';
const broken = codec.decode(brokenInput);
log('decode(', brokenInput, ')');
log('  → ok?', broken.ok, '— error type:', broken.error.constructor.name, '— DecodeError, not SchemaError');
JSON codec with schema validator

Binary codec

The binary codec uses 4-byte big-endian length-prefixed frames. Useful for audio data where JSON overhead is wasteful. 

// Encode binary data — 4-byte length header + payload
const payload = new Uint8Array([0xDE, 0xAD, 0xBE, 0xEF]);
const hex = (arr) => Array.from(arr).map(b => '0x' + b.toString(16).toUpperCase()).join(' ');

log('encode([', hex(payload), '])');
const encoded = binaryCodec.encode(payload);
log('  → ok?', encoded.ok, '—', encoded.value.length, 'bytes (4 header + 4 payload)');

// Decode it back — should match original
log('decode( encoded frame )');
const decoded = binaryCodec.decode(encoded.value);
log('  → ok?', decoded.ok, '— payload: [', hex(decoded.value), ']');

// Truncated frame — header says 10 bytes but only 2 present
const truncated = new Uint8Array([0, 0, 0, 10, 1, 2]);
log('decode([ header says 10 bytes, only 2 present ])');
const bad = binaryCodec.decode(truncated);
log('  → ok?', bad.ok, '— error:', bad.error.message);
binaryCodec — length-prefixed frames

8. Full scenario: Chat replay

This scenario demonstrates the primary use case for the stream library's buffer: a subscriber joins late and replays missed messages, then receives live messages going forward. This is how chat history works after a page reload or reconnect. 

// Create a persistent chat stream with dedup
const inner = createStream({ name: 'chat:porter', bufferCapacity: 2000 });
const stream = createDeduplicatedStream(
  inner,
  createDedup(createTimedCache({ ttlMs: 5000 })),
  (msg) => String(msg.id),
);

// Simulate 10 messages arriving while the user is away
for (let i = 1; i <= 10; i++) {
  stream.append({ id: i, text: 'message ' + i });
}
log('10 messages arrived while user was away');
log('---');

// User reconnects — their cursor was at seq 5 (they saw messages 1-6)
const cursor = createSequenceNumber(5);
const missed = stream.since(cursor);
log('Replay from seq 5 (' + missed.length + ' missed messages):');
missed.forEach(e => log('  seq=' + e.seq + ' → ' + e.payload.text));

// Now subscribe for live messages
log('---');
const live = [];
stream.on((env) => live.push(env.payload));

// New messages arrive
stream.append({ id: 11, text: 'message 11' });
stream.append({ id: 12, text: 'message 12' });

// Duplicate re-sent on reconnect — dedup catches it
stream.append({ id: 11, text: 'message 11 (resent)' });

log('Live messages received: ' + live.length);
live.forEach(m => log('  ' + m.text));
log('Duplicate "message 11 (resent)" was filtered by dedup.');

// latest(n) for initial page load
log('---');
const recent = stream.latest(3);
log('latest(3) for initial load:');
recent.forEach(e => log('  ' + e.payload.text));
Reconnect, replay missed messages, dedup re-sends

9. Full scenario: Voice round-trip

Voice uses two separate streams: one for binary audio frames (small buffer, high throughput) and one for JSON control events (speech start/end, transcription, TTS). This demonstrates how the library handles both data types with the same API. 

// Audio stream — small buffer, binary payloads
const audioStream = createStream({ name: 'voice-audio', bufferCapacity: 50 });

// Event stream — JSON voice protocol events
const eventStream = createStream({ name: 'voice-events', bufferCapacity: 200 });

const audioFrames = [];
const voiceEvents = [];

audioStream.on((env) => audioFrames.push(env.payload));
eventStream.on((env) => voiceEvents.push(env.payload));

// Simulate a voice round-trip: user speaks, system responds
log('=== User speaking ===');
eventStream.append({ type: 'speech_start' });

// Audio frames arrive during speech
audioStream.append(new Uint8Array([0x01, 0x02, 0x03, 0x04]));
audioStream.append(new Uint8Array([0x05, 0x06, 0x07, 0x08]));
audioStream.append(new Uint8Array([0x09, 0x0A, 0x0B, 0x0C]));

eventStream.append({ type: 'speech_end' });

log('=== Processing ===');
eventStream.append({
  type: 'transcription',
  id: 'tx-1',
  text: 'what is the build status',
});

log('=== System responding ===');
eventStream.append({ type: 'tts_start' });
// (TTS audio frames would go on audioStream here)
eventStream.append({ type: 'tts_end' });

log('Audio frames received:', audioFrames.length);
audioFrames.forEach((f, i) =>
  log('  frame ' + i + ':', f.length, 'bytes')
);

log('---');
log('Voice events received:', voiceEvents.length);
voiceEvents.forEach(e => {
  let detail = e.type;
  if (e.text) detail += ' → "' + e.text + '"';
  log('  ' + detail);
});

// Verify sequence numbers are monotonic
const audioSeqs = audioStream.latest(10).map(e => e.seq);
const eventSeqs = eventStream.latest(10).map(e => e.seq);
log('---');
log('Audio seqs:', audioSeqs.join(', '));
log('Event seqs:', eventSeqs.join(', '));
Binary audio + JSON events on separate streams

10. Full scenario: Transport + Stream together

This ties it all together: a memory transport simulating a WebSocket connection, with a stream on each side. The server-side stream buffers messages; a "reconnecting" client replays what it missed. 

// Server-side stream with buffer
const serverStream = createStream({ name: 'server-events', bufferCapacity: 1000 });

// Memory transport simulating a WebSocket
const { client, server } = createMemoryTransport();
const codec = createJsonCodec();

// Server: when it appends to its stream, send over transport
serverStream.on((env) => {
  const encoded = codec.encode(env.payload);
  if (encoded.ok) {
    server.send(encoded.value);
  }
});

// Client: decode incoming messages
const clientReceived = [];
client.onMessage((data) => {
  const decoded = codec.decode(data);
  if (decoded.ok) {
    clientReceived.push(decoded.value);
  }
});

await client.open();
await server.open();

// Server publishes events
serverStream.append({ type: 'status', message: 'build starting' });
serverStream.append({ type: 'status', message: 'build 50%' });
serverStream.append({ type: 'status', message: 'build complete' });

log('Client received', clientReceived.length, 'messages via transport:');
clientReceived.forEach(m => log('  ' + m.type + ': ' + m.message));

// Simulate disconnect
log('---');
log('Client disconnects...');
client.close();

// Server keeps publishing while client is away
serverStream.append({ type: 'deploy', message: 'deploying v2.1' });
serverStream.append({ type: 'deploy', message: 'deploy complete' });
log('Server published 2 more while client was away');

// Client reconnects — replay from seq 2 (last message it saw)
log('---');
log('Client reconnects, replays from seq 2:');
const missed = serverStream.since(createSequenceNumber(2));
missed.forEach(e => log('  seq=' + e.seq + ' → ' + JSON.stringify(e.payload)));
log('(' + missed.length + ' missed messages recovered from buffer)');
Transport + stream + codec + reconnect replay
