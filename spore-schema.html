Spore Schema

Data model for seeds and spores, mapped to Linear's data model (Issue, Project, Attachment). Zero drift target.

Design principle: Our schema follows Linear's where possible. Deviations are called out as MCC extensions. The goal is zero drift — every field either maps 1:1 to Linear or is explicitly marked as an extension that we manage ourselves.

Spore Storage

Spores are not flat. They accumulate over time and need context management.

Directory Structure

mcc-tasks/
  seeds.json                 # All seeds (projects) — small, always loaded
  spores/
    active.json              # Live working set — all non-done spores
    archive/
      2026-11.json           # Done/canceled spores, partitioned by month
      2026-10.json

Rules

  • seeds.json is always loaded. Small file, all projects.
  • spores/active.json is the working set. Loaded by default in all views and by agents.
  • spores/archive/ is loaded on demand — when rendering "done" views, PM history, or time-based queries.
  • When a spore moves to done or canceled, it stays in active.json until the next sync cycle, then moves to the current month's archive.
  • An agent reading spores only needs active.json for current work. Archives are for history.

Sync Procedures

Pull: Source → Local

Drift Detection

On each sync, compare local spore state vs source state:

for each spore:
  for each source:
    remote_state = fetch from source API
    if remote_state != spore.state:
      flag drift: {
        spore_id,
        source_type,
        source_id,
        local_state: spore.state,
        remote_state,
        detected_at: now()
      }

Drift is surfaced as warnings in the UI. Resolution: human decides which direction to reconcile.

Procedural Metrics

Computed from local data only. No API calls at read time. Given a date range:

metrics(from, to) = {
  done:        count(spores where completed_at in [from, to])
  active:      count(spores where state in [todo, in_progress, review])
  review:      count(spores where state == review)
  backlog:     count(spores where state == backlog)
  open_prs:    count(spores with github_pr source, state != done)
  human_owned: count(active spores where owner == human)
  machine_owned: count(active spores where owner == machine)
  drift:       count(flagged drift items)
}

The PM report renders these as the dashboard. An LLM interpretation layer runs on top for suggestions and risk analysis.
