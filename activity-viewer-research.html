Activity Viewer Landscape

Who else is building session viewers and observability tools for AI coding agents — and where the gaps are.

TL;DR

There are ~15 open-source Claude Code JSONL viewers and three major observability platforms (Langfuse, LangSmith, W&B Weave) with native Claude Code integrations. Almost all focus on cost/token analytics, browsable conversation history, and static traces. What nobody does: a first-class agent state model — tracking background tasks, teammate dispatch, and their lifecycle as they run. The WebSocket-served real-time feed, timeline scrubber, and jq-style field filters we built in mcc-activity are largely absent from this space.

Landscape — What Exists

The ecosystem splits into three tiers: local JSONL viewers (tightly Claude Code-specific), platform observability tools (framework-agnostic, hook-based), and cross-agent tools (support Cursor, Devin, Aider, etc.).

Tier 1 — Claude Code JSONL Viewers

Claudoscope Claude Code

github.com/cordwainersmith/claudoscope — Native macOS app, MIT, Swift/SwiftUI

Native macOS menu bar app that monitors ~/.claude/projects/ via FSEvents. Browses session history, searches across conversations, tracks token cost per project, detects leaked credentials in session files in real time, and lints CLAUDE.md configs (19 rules). Sends native macOS notifications when Claude needs permission or finishes a turn. Zero telemetry, fully local.

Differentiator: secrets detection + config linting inside the viewer. Only tool that actively monitors for credential leaks in transcripts.

claude-code-trace Claude Code

github.com/delexw/claude-code-trace — TypeScript, web + TUI

Session log viewer for ~/.claude/projects JSONL files. Browses conversations, tool calls, tokens, and live-tails active sessions. Available as a desktop app, web UI, and TUI (terminal).

Differentiator: TUI mode — the only viewer that works in the terminal without a browser.

claude-transcript-viewer Claude Code

github.com/WiseeCarrot/claude-transcript-viewer — Tauri/Rust desktop app

Tauri + Rust desktop app that turns raw JSONL logs into a browsable timeline. Tool calls are paired with their outputs, replies are markdown-rendered, and full-text search works across every session.

Differentiator: Tauri/Rust stack — closest to what mcc-activity chose (Rust WebSocket server). Tool call + output pairing as a first-class UI unit.

claude-session-visualizer Claude Code

github.com/anaypaul/claude-session-visualizer — TypeScript, React Flow

Live visualization dashboard. Renders session execution as an interactive graph (React Flow) with error highlighting — failed tool calls glow red. Includes token burn charts, thinking trace explorer, and an error replay feature: a density strip on the timeline marks error locations, clicking shows the tool name, input, error message, and what happened next.

Differentiator: execution trees + error replay. The only tool with a visual dependency graph of tool calls and an error-focused replay UI.

session-tree Claude Code

github.com/roykollensvendsen/session-tree — TypeScript

Live task-graph view of every Claude Code session on the machine. Supports replay — walk any session back through its history with your own prompts on the timeline.

Differentiator: interactive replay with the user's own prompts on the timeline — the most direct competitor to a scrubber-style replay.

token-dashboard Claude Code

github.com/nateherkai/token-dashboard — TypeScript

Per-prompt cost analytics, tool/file heatmaps, subagent attribution, cache analytics, and project comparisons — all from the JSONL transcripts.

Differentiator: cost analytics depth. Heatmaps by tool and file, subagent attribution per spend — the most sophisticated cost breakdown.

claude-code-command-center Claude Code

github.com/amahpour/claude-code-command-center — TypeScript, web

Web-based dashboard for monitoring multiple Claude Code sessions simultaneously. JSONL Watcher monitors ~/.claude/projects/ for changes, shows session status, token usage, active tools, and subagents across all terminal instances at a glance.

Differentiator: multi-session monitoring in one view. Designed explicitly for running multiple Claude Code instances in parallel.

transcript-viewer Claude Code

github.com/juckele/transcript-viewer — TypeScript, local web

Live local web viewer for session transcripts and token spend. Pages update live as sessions are written.

Differentiator: minimal — focused solely on live update fidelity without a heavy UI layer.

Tier 2 — Platform Observability (Hook-Based)

Langfuse Claude Code

langfuse.com/integrations/developer-tools/claude-code — Open source + hosted

Hooks into Claude Code's lifecycle (stop hook) to ship sessions to Langfuse as traces. Each conversation turn, tool call, and model response becomes a structured trace with properly nested observations — including thinking blocks and token usage. Timestamps are backdated to match the original session timing. Supports team usage dashboards: attaches user identity so token spend can be broken down by developer or project.

Differentiator: proper trace nesting with thinking blocks. Most complete representation of multi-step tool-use loops in a trace store.

LangSmith Claude Code

devs30.com — LangChain / LangSmith — Hosted (commercial)

Hooks into nine Claude Code lifecycle points: UserPromptSubmit, PreToolUse, PostToolUse, Stop, StopFailure, SubagentStop, PreCompact, PostCompact, SessionEnd. Each message is its own trace; tool and subagent spans nest inside. Ships traces to LangSmith where they can be clustered into Insights, used to build eval datasets, and monitored for regressions.

Differentiator: nine lifecycle hooks — the most granular Claude Code integration. SubagentStop + PreCompact hooks capture events no other platform sees.

W&B Weave Claude Code

docs.wandb.ai — Weights & Biases Weave — Hosted (commercial + free tier)

Plugin traces every Claude Code session automatically — no code changes required. Ships user prompts, Claude responses, tool inputs and outputs, file contents, shell commands, and fetched URLs. Each session is a top-level trace; individual turns and tool calls are child entries in the Traces tab. Rebuilt in 2026 specifically to handle agent debugging failures in production.

Differentiator: zero-code install (npm install -g weave-claude-code) — lowest friction of the platform integrations.

AgentOps Partial

github.com/AgentOps-AI/agentops — Python SDK, open source + hosted

Python SDK for AI agent monitoring. Records an agent's entire session — every LLM call, tool invocation, and step — and supports visual session replay with rewind and point-in-time control. Tracks token cost, latency, and errors. Renders inter-agent interactions as connected flows showing how messages and control pass between agents. Covers 400+ LLM models. Primary integration path is Python-based agents (CrewAI, OpenAI Agents SDK, LangChain, AutoGen); Claude Code hooks are possible via the event API but not first-class.

Differentiator: multi-agent flow visualization — the best tool for seeing how control passes between agents in a network, not just within one session.

Tier 3 — Cross-Agent / Multi-Tool

AgentsView Claude Code

github.com/kenn-io/agentsview — TypeScript

Local-first session search, analytics, and token statistics for coding agents. Supports Claude Code, Codex, Cursor, Aider, Devin CLI, OpenHands CLI, and 50+ others. Tool sequences dashboard follows errors, retries, tool switches, and recovery chains back to their recorded calls.

Differentiator: cross-agent breadth — unified interface for 50+ agents, the only tool that lets you compare tool call patterns across Claude Code vs Cursor vs Aider.

cursor-trace Cursor only

github.com/dwqs/cursor-trace — TypeScript

Browses and visualizes Cursor AI agent session transcripts. Features thinking detection, tool call inspection, session browser listing all projects and agent sessions, and HTML export.

Differentiator: thinking block detection — identifies and surfaces model reasoning separately from tool output, applicable pattern for any agent viewer.

OpenHands observability OpenHands only

docs.openhands.dev — OpenHands (All-Hands AI)

Full session replay from the event log. The conversation is a typed stream of immutable Action and Observation Pydantic events — replayable by design. Supports pause, resume, fork, deterministic replay, and full audit trails. Browser interactions are recorded using rrweb (DOM mutations, mouse, scroll), saved as JSON, and replayed in-browser.

Differentiator: deterministic replay as a first-class architectural guarantee, not a bolted-on viewer. rrweb-based browser session recording is unique in this space.

Gaps — What Nobody Does

Areas where the existing ecosystem has no coverage or only shallow support.

Agent state model for dispatched work No existing viewer tracks background tasks, teammate dispatches, and their lifecycle (pending, running, failed, done) as first-class entities in the UI. All tools treat the transcript as a linear event log — none model the supervisor's mental state: "I dispatched X to teammate Y, it's on branch Z, here is its current status."
Reverse-chronological event display Every viewer shows events in chronological order (oldest first). For a long-running session that's been running for hours, the most recent activity is buried at the bottom. mcc-activity shows newest first by default — none of the surveyed tools do this.
jq-style field filters for JSONL Langfuse has trace query filters. No local viewer offers jq-style dot-notation filters against arbitrary JSONL fields. The most common viewer search is free-text across rendered content — not structured field access.
Multi-agent state across hosts AgentOps visualizes inter-agent flows but only within a single Python process tree. No tool models agents running in separate Docker containers on separate branches with separate JSONL files, all rendered into one coherent activity view.
WebSocket-served real-time feed as a shareable service All local viewers are either browser-only (read direct from filesystem via Tauri/Electron) or platform-hosted. No tool exposes a WebSocket endpoint that any browser — including a mobile device on the same network — can connect to and receive a live event stream from.
Rust + local-first + network-accessible Tauri/Rust for the desktop case exists (claude-transcript-viewer). A Rust WebSocket server that exposes the stream over the network without requiring a cloud account does not exist in this space.
Session-level agent health signals Claudoscope detects when Claude is blocked on a permission. No tool surfaces higher-level health signals: "this agent hasn't made a tool call in N minutes", "this subagent's last 3 tool calls all failed", "token burn rate is 3x normal for this session type."

Opportunities

What we could learn from, borrow, or potentially integrate with.

Error replay UI from claude-session-visualizer
The error density strip — a timeline axis with red dots at error locations — is a compact and useful pattern. Combining it with the scrubber gives both spatial ("many errors in this region") and temporal ("jump to this exact error") navigation. Worth adopting.
Thinking block surfacing from cursor-trace
Identifying and rendering model reasoning separately from tool I/O is a broadly applicable pattern. If the JSONL includes thinking events, surfacing them as a distinct collapsible section next to the tool call that follows would help debugging.
Langfuse trace queries as a filter model
Langfuse's trace query interface (filter by model, duration, cost, tag) is more discoverable than raw jq syntax for most users. Offering a preset filter palette alongside free-form jq filters would lower the entry bar without sacrificing power.
AgentOps multi-agent flow graph
When a supervisor dispatches to teammates, those relationships could be rendered as a connected graph — not just a flat list. AgentOps' inter-agent flow visualization is the reference design. Applicable once mcc-activity tracks multi-agent sessions.
OpenHands deterministic replay
OpenHands' immutable Action/Observation event stream is the right model for deterministic replay. If mcc-activity's event model is append-only and typed, it could support forked replay: "replay from event N with a different input at step M." Currently no tool in this space except OpenHands does this.
AgentsView as a potential data source aggregator
AgentsView already parses 50+ agent formats. Rather than writing parsers for Cursor/Aider/Devin logs ourselves, feeding those through AgentsView's normalization layer and consuming its output format could make mcc-activity cross-agent without maintaining N parsers.
W&B Weave plugin architecture (zero-code install)
Weave's install path (npm install -g weave-claude-code && weave-claude-code install) registers itself as a Claude Code hook with no changes to the agent. If mcc-activity were to offer a push-based mode (agent pushes events to the server via a hook), this install pattern is the right model.
