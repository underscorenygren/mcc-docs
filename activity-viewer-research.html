Activity Viewer Landscape

Who else is building dashboards and observability tools for AI coding agent sessions — and where mcc-activity fits.

Context: We built mcc-activity — a Rust WebSocket server that tails Claude Code's JSONL session transcripts and serves a browser UI showing agent activity in real time. Features: reverse-chronological event display, an agent state model tracking background tasks and teammates, a timeline scrubber, free-text search, and jq-style field filters. This document surveys what else exists and where the gaps are.

TL;DR

The space splits cleanly into three tiers. JSONL-specific tools (mostly hobby/solo GitHub projects) read Claude Code transcripts directly — closest to what we built, but oriented toward post-hoc browsing, not live multi-agent state. Multi-agent coding viewers (AgentsView, ClawMetry) aggregate across 50+ agents and focus on cost and transcript search. Production observability platforms (Langfuse, AgentOps, W&B Weave) are cloud-hosted, instrumentation-heavy, and built for teams running agents at scale. Nobody has built a live, state-model-aware viewer that understands teammates, background tasks, and the relationship between concurrent sessions.

Landscape

1. Claude Code JSONL Viewers (GitHub, solo projects)

These tools appeared quickly after Claude Code shipped its JSONL transcript format. They share a common shape: watch ~/.claude/projects/, parse messages, render in a browser or desktop app.

transcript-viewer — juckele
Local web app. Reads JSONL session files and shows where tokens went per prompt. Live updates as the session is written. Lightweight, no dependencies beyond a static server.
Claude Code specific: Yes. Key differentiator: Token spend focus — cost per prompt, not just message display.
claude-transcript-viewer — WiseeCarrot
Tauri/Rust desktop app. Turns JSONL logs into a browsable timeline: tool calls paired with their outputs, markdown-rendered assistant replies, full-text search across all sessions.
Claude Code specific: Yes. Key differentiator: Native desktop app (Tauri); offline-first with cross-session search.
ClaudeCodeTranscriptViewer — ly4096x
Zero-dependency web UI. Renders JSONL transcripts in Claude Code's own visual style in-browser. Drop a file or point at a local path.
Claude Code specific: Yes. Key differentiator: Fidelity — replicates the Claude Code chat appearance.
claude-session-visualizer — anaypaul
Live visualization dashboard built with TypeScript + React Flow. Renders execution trees (interactive graph with pan/zoom/minimap), token burn charts, a thinking explorer, and error replay. Supports both JSONL file-watching and direct HTTP hooks from Claude Code for lower-latency updates.
Claude Code specific: Yes. Key differentiator: Execution graph — visualizes the dependency tree of tool calls, not just a flat list.
claude-code-trace — delexw
Multi-platform: desktop app, web app, and terminal UI. Browses conversations, tool calls, and token usage.
Claude Code specific: Yes. Key differentiator: Three frontends (desktop/web/TUI) from one codebase.
claude-code-command-center — amahpour
Web dashboard for monitoring multiple Claude Code sessions simultaneously. JSONL watcher monitors ~/.claude/projects/ for changes, surfaces session status and cost in a live grid.
Claude Code specific: Yes. Key differentiator: Multi-session management — the first tool oriented toward running several sessions at once.
claude-view — tombelieber
"10 Claude sessions running. What are they doing?" Live dashboard for monitoring, cost tracking, search, and sub-agent visibility.
Claude Code specific: Yes. Key differentiator: Explicitly scoped to concurrent parallel sessions — closest competitor to our multi-agent view.
Token-Dashboard — Arylmera
Rust + Tauri desktop app. Per-prompt cost, tool heatmaps, subagent attribution, cache analytics, and a rule-based tips engine. Fully offline.
Claude Code specific: Yes. Key differentiator: Tool heatmaps and cache analytics — cost optimization angle, not just visibility.

2. Multi-Agent Coding Session Viewers

These tools aggregate across many agents (Claude Code, Codex, Cursor, Aider, OpenHands, Devin, and 40+ others) and focus on cross-agent search, cost aggregation, and long-term session archives.

AgentsView — kenn-io
Local-first. Supports 50+ agents. Full transcript with structured tool calls, results, reasoning, and diffs. Browses sub-agent runs nested beneath their launching sessions. Full-text search with optional semantic search (OpenAI-compatible embeddings). A "recall corpus" browser extracts knowledge from sessions.
Claude Code specific: Yes (plus 50 others). Key differentiator: Sub-agent hierarchy navigation and knowledge extraction from transcripts.
agentsview.io
ClawMetry
Renders sessions, transcript, token splits, and cost across every agent you run in one dashboard. Supports OpenHands, Claude Code, and others. Shows instructions, agent reasoning, every command run, every file edited, every page opened.
Claude Code specific: Yes (plus others). Key differentiator: Unified cross-agent cost dashboard with full action log.
cursor-trace — dwqs
VS Code extension for Cursor AI Agent session transcripts. Thinking detection, tool call inspection, and HTML export. Opens sessions in a webview with user messages, assistant steps, and collapsible thinking blocks.
Claude Code specific: No — Cursor only. Key differentiator: IDE-embedded viewer as an extension, not a separate app.

3. Production Observability Platforms

These are cloud-hosted, instrumentation-required platforms built for teams. They are not transcript parsers — they receive structured telemetry via SDK, proxy, or hooks. Some have added Claude Code support as a specific integration.

Langfuse — Claude Code Integration
Cloud-hosted. Uses Claude Code lifecycle hooks to ship each session to Langfuse as structured traces. Groups turns from the same session via a shared session_id. Captures user inputs, assistant responses, tool invocations, and tool I/O. MCP server covers 15 tool categories so Claude Code can query Langfuse data programmatically.
Claude Code specific: Yes — explicit integration. Key differentiator: Full LLM eval platform (evals, prompts, A/B) with Claude Code as one input source.
Tracing coding agents: Claude Code, Codex, Copilot
Weights & Biases Weave — Claude Code plugin
Cloud-hosted. A plugin traces every Claude Code session automatically — no code changes required. Logs every turn, tool call, and sub-agent to Weave's structured session store. Supports debugging, audit, cost tracking, and latency monitoring.
Claude Code specific: Yes — dedicated plugin. Key differentiator: Zero-instrumentation setup; integrates with W&B experiment tracking and ML pipelines.
AgentOps
Cloud-hosted. Purpose-built for agentic workloads. Session replay with rewind: records every LLM call, tool invocation, and step, then lets you replay it visually. Time-travel debugging, audit trail, cost tracking across 400+ LLMs, anomaly detection.
Claude Code specific: Via Claude SDK instrumentation, not a transcript hook. Key differentiator: Time-travel debugging with rewind to any point in a session.
Braintrust
Cloud-hosted eval and observability platform. MCP server integrates with Claude Code, Cursor, VS Code, and Windsurf — IDE-native trace querying. Logs tool calls with timing to identify slow dependencies.
Claude Code specific: Yes — MCP server integration. Key differentiator: Eval-first: traces feed directly into prompt evaluation and regression testing.
Helicone
Cloud proxy. Groups related requests as sessions via Helicone-Session-Id header. Lightweight, drop-in, per-request cost and session traces. Best for API-level monitoring, not transcript parsing.
Claude Code specific: No — Claude API proxy only, not a JSONL reader. Key differentiator: Zero-instrumentation proxy; no SDK required.
LangSmith
Cloud-hosted. Tracing via decorators and SDK wrappers. Claude Agent SDK instrumentation available. Does not parse Claude Code JSONL transcripts directly.
Claude Code specific: Via Claude SDK, not transcript hooks. Key differentiator: Tight LangChain integration; strongest for LangGraph agent debugging.

Gaps

What nobody in this space does:

Agent state model
Every tool presents a flat or tree-shaped list of events. None model the agent as a stateful entity with named background tasks, teammates in known states, and a distinction between "Claude is thinking" vs. "Claude dispatched work and is waiting." mcc-activity tracks this explicitly — the viewer knows whether the supervisor is idle, working, waiting for a build, or blocked on a teammate.
Multi-session relationship graph
claude-view shows N sessions side-by-side, but treats them as independent streams. AgentsView nests sub-agent runs but only for sessions that called each other. No tool shows the relationship between a supervisor session and its teammates as a live topology with message flow between them.
jq-style field filters
Several tools offer full-text search and date filters. None expose a query language for filtering events by field path — e.g., show only tool_use events where tool_name = "Bash" and duration_ms > 5000.
WebSocket push (not file polling)
Most JSONL viewers poll the filesystem or use inotify and SSE. mcc-activity runs a Rust WebSocket server that pushes events directly to the browser — lower latency, no missed events during rapid writes, and a single connection shared across all browser tabs. This architecture also makes it straightforward to add non-JSONL event sources (sysbus, chatbus).
Source merging (JSONL + bus events)
All existing tools read only JSONL transcripts. mcc-activity can merge events from the sysbus and chatbus alongside JSONL data — so the viewer can show "build started" (sysbus) interleaved with the tool call that triggered it (JSONL), giving a unified timeline that spans the agent and the infrastructure it drives.

Opportunities

Langfuse integration
Langfuse's Claude Code hook already parses JSONL and ships structured traces. Rather than duplicating that parsing, mcc-activity could optionally push to Langfuse (or consume from it via its MCP server) to give sessions a persistent cloud-backed eval trail. Local-first for live view; Langfuse for archival and evaluation.
Ref: langfuse.com/integrations/developer-tools/claude-code
AgentsView's sub-agent nesting model
AgentsView's approach to navigating sub-agent hierarchies — where a launching session shows each delegation's prompt and result — is well-designed for the supervisor/teammate topology. Worth studying for how mcc-activity exposes teammate state without requiring the user to open a separate session tab.
Ref: github.com/kenn-io/agentsview
claude-session-visualizer's execution graph
React Flow execution trees for tool call dependencies is the best visual representation of "what did the agent actually do" in a single session. The graph model (not a list) is worth considering for mcc-activity's per-session drill-down view, even if the top-level remains a chronological feed.
Ref: github.com/anaypaul/claude-session-visualizer
W&B Weave's zero-instrumentation approach
Weave's Claude Code plugin requires no code changes — it hooks in via the same lifecycle mechanism that Langfuse uses. mcc-activity already operates this way (JSONL tail, no SDK). The opportunity is positioning: advertise that mcc-activity is the local, self-hosted equivalent — same zero-instrumentation promise, fully offline, Rust performance.
Ref: W&B Weave Claude Code plugin docs
Token heatmaps and cache analytics
Token-Dashboard (Rust/Tauri) has tool heatmaps and cache analytics that mcc-activity does not. These are purely derived from JSONL data we already parse. Adding a cost/cache layer to the existing viewer would close the gap without changing the architecture.
Ref: github.com/Arylmera/Token-Dashboard
