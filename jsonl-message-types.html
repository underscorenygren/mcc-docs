JSONL Message Types

Reference for Claude Code session transcript format — 7 message types, sorted by viewer priority.

Key Learnings

Teammate conversations are NOT in the main JSONL. Subagent (teammate) messages only exist in task output files under /tmp/claude-1001/.../tasks/<agentId>.output. The main transcript gets progress events (type agent_progress) that relay what the teammate is doing, but these are always isSidechain: false. Zero isSidechain: true messages appear in the main JSONL.
isSidechain and run_in_background are orthogonal. isSidechain means "subagent conversation" — it only appears in task output files. run_in_background is a Bash tool parameter meaning "don't block the conversation." A background Bash command from the supervisor has isSidechain: false.
Task output files don't contain exit signals. Background Bash files end with whatever the command last printed. Teammate JSONL files end at the last agent message. The exit/completion signal only exists in the main JSONL as a task-notification user message (or queue-operation enqueue).
Two file formats in /tmp/tasks/. Plain text = background Bash command output. JSONL (first char {) = teammate agent transcript. The filename is either a short alphanumeric ID (Bash) or a longer hex agent ID (teammate).
slug is a random session name. Like Docker container names — human-readable, cosmetic only. Example: "slug": "optimized-plotting-eclipse". Not used for routing or lookup.

Background Task Lifecycle — Annotated Example

A supervisor dispatches sleep 10 as a background Bash command. Here is every message that appears in the main JSONL, in order.

Step 1: Tool dispatch

The supervisor's assistant message contains a tool_use block. Note run_in_background: true and isSidechain: false — this is the main thread, not a subagent.

{
  "parentUuid": "da2ca598-...",
  "isSidechain": false,
  "type": "assistant",
  "message": {
    "role": "assistant",
    "content": [
      {
        "type": "tool_use",
        "id": "toolu_018VsYPFDWg6SBKZsUxbFfgR",
        "name": "Bash",
        "input": {
          "command": "sleep 10",
          "description": "Sleep 10 seconds for data inspection",
          "run_in_background": true
        }
      }
    ]
  }
}

Step 2: Immediate tool_result

The harness returns immediately with a task ID and output file path. The command is running but hasn't finished.

{
  "isSidechain": false,
  "type": "user",
  "message": {
    "role": "user",
    "content": [
      {
        "tool_use_id": "toolu_018VsYPFDWg6SBKZsUxbFfgR",
        "type": "tool_result",
        "content": "Command running in background with ID: bpw0aypub. Output is being written to: /tmp/claude-1001/.../tasks/bpw0aypub.output"
      }
    ]
  },
  "toolUseResult": {
    "backgroundTaskId": "bpw0aypub"
  }
}

Step 3: Completion notification

10 seconds later, a queue-operation enqueues the notification, then it arrives as a user message with XML-structured content. This is the only exit signal in the main JSONL.

{
  "type": "queue-operation",
  "operation": "enqueue",
  "content": "<task-notification>\n<task-id>bpw0aypub</task-id>\n<tool-use-id>toolu_018VsYPFDWg6SBKZsUxbFfgR</tool-use-id>\n<status>completed</status>\n<summary>Background command \"Sleep 10 seconds\" completed (exit code 0)</summary>\n</task-notification>"
}
{
  "isSidechain": false,
  "type": "user",
  "message": {
    "role": "user",
    "content": "<task-notification>\n<task-id>bpw0aypub</task-id>\n<status>completed</status>\n<summary>Background command \"Sleep 10 seconds\" completed (exit code 0)</summary>\n</task-notification>"
  }
}

Teammate Lifecycle — Annotated Example

A supervisor dispatches a teammate via the Agent tool to run sleep 5. Here is what appears in the main JSONL vs the task output file.

Step 1: Agent tool dispatch

The supervisor calls the Agent tool. This is a regular assistant message, isSidechain: false.

{
  "isSidechain": false,
  "type": "assistant",
  "message": {
    "role": "assistant",
    "content": [
      {
        "type": "tool_use",
        "id": "toolu_014yss8RQ66CT5ZiafmxaxgH",
        "name": "Agent",
        "input": {
          "description": "Sleep 5 seconds for trace",
          "prompt": "Run this command: sleep 5. That's it.",
          "model": "haiku"
        }
      }
    ]
  }
}

Step 2: Progress relay — prompt delivered

The main JSONL receives progress events with data.type: "agent_progress" that relay the teammate's activity. Note: isSidechain: false — these are the main thread's view of the subagent.

{
  "isSidechain": false,
  "type": "progress",
  "data": {
    "type": "agent_progress",
    "agentId": "a4640a5c49d8f7782",
    "prompt": "Run this command: sleep 5. That's it.",
    "message": {
      "type": "user",
      "message": {
        "role": "user",
        "content": [{ "type": "text", "text": "Run this command: sleep 5..." }]
      }
    }
  },
  "toolUseID": "agent_msg_011Ch8yrEmTDPpp9yzfvWK9B",
  "parentToolUseID": "toolu_014yss8RQ66CT5ZiafmxaxgH"
}

Step 3: Progress relay — tool result

The teammate's Bash output is relayed as another agent_progress event.

{
  "isSidechain": false,
  "type": "progress",
  "data": {
    "type": "agent_progress",
    "agentId": "a4640a5c49d8f7782",
    "message": {
      "type": "user",
      "message": {
        "role": "user",
        "content": [{
          "tool_use_id": "toolu_01X5u2noNLczX8CK3PNFV62m",
          "type": "tool_result",
          "content": "(Bash completed with no output)"
        }]
      }
    }
  }
}

Step 4: Agent tool_result

When the teammate finishes, the Agent tool returns a tool_result to the supervisor — same pattern as any other tool call.

What's in the task output file

The file /tmp/.../tasks/a4640a5c49d8f7782.output contains the teammate's full JSONL conversation. These messages have isSidechain: true and agentId set. This is the only place these messages exist — they are not in the main JSONL.

// First line: the prompt delivered to the teammate
{
  "isSidechain": true,
  "agentId": "a4640a5c49d8f7782",
  "type": "user",
  "message": {
    "role": "user",
    "content": "Run this command: sleep 5. That's it."
  }
}
// Subsequent lines: assistant responses, tool_use, tool_result, progress...
// Same 7 message types, but all marked isSidechain: true

Data Location Summary

WhatWhereFormat
Main session transcript ~/.claude/projects/<project>/<sessionId>.jsonl JSONL, all isSidechain: false
Teammate transcripts /tmp/claude-1001/.../tasks/<agentId>.output JSONL, all isSidechain: true
Background Bash output /tmp/claude-1001/.../tasks/<taskId>.output Plain text (stdout/stderr)

To distinguish task output files: if the first character is {, it's a teammate JSONL transcript. Otherwise, it's plain text from a background Bash command.

Message Types

assistant 17,693 messages HIGH

Agent responses — text output and tool calls. This is where the work happens. The message.content array contains blocks:

Block typeCountDescription
tool_use~12,000Tool invocations — the actual work
text4,359Agent's text output (reasoning, chat)

Top tools called:

  • Bash (4,666) — Shell commands
  • mcp__chat-bridge__reply (3,604) — Chat messages
  • Read (1,637) — File reads
  • Edit (1,248) — File edits
  • Grep (610) — Code search
  • Write (436) — File creation
  • ToolSearch (234) — Deferred tool loading

  • TaskUpdate (135) — Task state changes
  • TaskCreate (72) — Task creation
  • Glob (66) — File pattern matching
  • WebSearch (45) — Web search
  • WebFetch (23) — URL fetch

Key fields: timestamp, sessionId, requestId, cwd, gitBranch, isSidechain

Human input and tool results. Two kinds:

KindCountDescription
Human messages1,448Actual user input. message.content is a string.
Tool results12,958Return values from tool calls. message.content is an array of tool_result blocks.

Origin kinds distinguish where the message came from:

OriginCountDescription
(none)13,034Tool results and direct terminal input

Key fields: origin.kind, permissionMode, isMeta, promptId

system 1,750 messages MEDIUM

Internal lifecycle events. Useful for understanding session structure.

SubtypeCountDescription
stop_hook_summary1,194Hook execution after each turn (sysbus signals, etc.)
turn_duration487Timing data for each agent turn
compact_boundary58Context window compaction — older messages summarized
api_error13API failures (rate limits, network errors)

Key fields: subtype, hookInfos, stopReason, level

queue-operation 4,378 messages LOW

Internal message routing. Operations: enqueue (2,189), dequeue (1,388), remove (801).

These track how user messages flow through the internal queue. Each enqueue/dequeue pair is one message being processed. Task notifications are enqueued here before being delivered as user messages.

Key fields: operation, content

progress 31,143 messages VERY LOW

Streaming and hook progress events. Filter these out by default — they are noise for most purposes. Exception: agent_progress events are the only way to observe teammate activity from the main JSONL.

SubtypeCountDescription
hook_progress30,476Pre/post tool hooks (permission checks, sysbus signals)
agent_progress588Subagent activity relay — the main thread's view of teammate work
query_update45Search query refinements
search_results_received45Search results arriving

Key fields: data.type, toolUseID, parentToolUseID, data.agentId (for agent_progress)

file-history-snapshot 182 messages LOW

Periodic snapshots of tracked file states. Used for undo/restore. Contains snapshot.trackedFileBackups with file contents at that point in time.

last-prompt 30 messages LOW

Session bookmarks. Records the last user prompt for session resumption. Contains lastPrompt (the text) and sessionId.

Viewer Recommendations

Default view
Show assistant (tool_use + text) and user (channel origin only). Hide tool_result, progress, queue-operation.
Task view
Filter to assistant messages containing TaskCreate, TaskUpdate, TaskGet tool_use blocks. Show full context.
Teammate view
Filter progress events where data.type === "agent_progress". Group by data.agentId. For full detail, read the corresponding task output file.
Background task view
Track background commands: find tool_use blocks with run_in_background: true, match to task-notification user messages via the tool-use-id field. Gap between dispatch and notification = execution time.
Debug view
Show everything including progress and system events.
Timeline markers
Use system.compact_boundary to mark context window resets. Use system.turn_duration for timing analysis.
