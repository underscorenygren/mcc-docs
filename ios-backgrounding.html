What Keeps an App Alive in Background

1. Audio Background Mode (what we use)

The UIBackgroundModes: ["audio"] entitlement tells iOS the app plays or records audio. As long as an AVAudioSession is actively playing or recording, iOS keeps the app running with full network access.

  • Recording active: mic stream keeps process alive, WebSockets stay connected, full functionality
  • Audio playing (ambient sounds, TTS): same — process stays alive
  • Audio stops: iOS gives ~30s grace, then suspends the app. WebSockets die silently.

This is how YouTube, Spotify, and podcast apps work. No audio = no background.

2. VoIP Push (higher priority)

The UIBackgroundModes: ["voip"] entitlement enables VoIP push notifications via PushKit. These wake the app with higher priority than regular silent pushes. Apple requires actual VoIP functionality.

3. Silent Push Notifications

APNs can deliver a content-available: 1 push that wakes the app for ~30s of background execution. iOS throttles these to roughly 2-3 per hour. Used by WhatsApp, Telegram for background message delivery.

4. Background Tasks (BGTaskScheduler)

iOS 13+ API for deferred work. Not suitable for real-time messaging — iOS decides when to run them.

Our Current Implementation

Suspend/Resume Events

// Typed events (shared/core/orch-events.ts)
Evt.App.Suspend  — 'app:suspend'
Evt.App.Resume   — 'app:resume'

// Mobile: React Native AppState listener
RNAppState.addEventListener("change", (state) => {
  if (state === "active")     bus.emit(Evt.App.Resume, {});
  if (state === "background") bus.emit(Evt.App.Suspend, {});
});

// Web: visibilitychange listener
document.addEventListener("visibilitychange", () => {
  bus.emit(document.hidden ? Evt.App.Suspend : Evt.App.Resume, {});
});

On Resume

  • Reconnect voice WS if disconnected

Disconnect Sound

Both web and mobile play an error chime (synth/error.wav) when a WebSocket drops. This gives the user an audible signal that iOS may have frozen the app.

Known Gaps

GapImpactSolutionEffort
No audio playing = app freezes Messages don't arrive, no TTS Silent audio loop when backgrounded, or push notifications Small (silent loop) / Medium (push)
WS dies silently after iOS suspension No messages until user returns to app Push notification wakes app briefly for message fetch + TTS Medium — needs APNs setup, server-side push
No reconnect after long suspension Auth token may expire during suspension On resume, check auth before reconnecting Small

Recommended Next Steps

  1. Silent audio keepalive: When app backgrounds and no audio is playing, start a silent AVAudioSession loop. Stop on resume. Minimal battery impact, keeps WS alive.
  2. Push notifications (expo-notifications): Server detects client disconnect, sends APNs silent push, app wakes for 30s, fetches message, plays TTS. Handles the case where audio keepalive eventually stops.
  3. VoIP push for priority delivery: Higher priority than regular silent push, but Apple reviews VoIP usage strictly.
