Slack Integration

Bidirectional bridge between Slack and the MCC supervisor via chatbus.

Live since November 2026

Current Setup

Status: live. The Slack connector service (cmd/slack/) is deployed and connected to the MCC workspace.

The system has three components:

1. Slack Connector Service (Go)

A lightweight Go service (cmd/slack/main.go, port 9093) that bridges Slack's API with the chatbus. It runs as a Docker container in the prod profile.

2. Inbound: Slack → Supervisor

User posts in #supervisor → Slack Events API sends POST to /webhook/slack → Signature verified (HMAC-SHA256 with signing secret) → Message published to chatbus: {agent: "supervisor", channel: "chat", direction: "in"} → Supervisor receives via chat-bridge, processes normally

The connector verifies every request using Slack's signing secret (HMAC-SHA256 of v0:timestamp:body). It handles the url_verification challenge automatically. Bot messages and edits are filtered out to prevent echo loops.

3. Outbound: Supervisor → Slack

Supervisor sends reply via chat-bridge → Chatbus stores message (supervisor/chat/out) → Slack connector polls chatbus every 2 seconds → New messages POSTed to Slack Incoming Webhook → Appears in #supervisor channel

The outbound poller skips messages that originated from Slack (prefix slack:) to prevent loops. It tracks the last-seen message ID to avoid duplicates.

What Lisa Sees

Lisa (and any workspace member) can post in #supervisor and the message reaches the supervisor as if it were typed in the web chat. The supervisor's replies appear in the channel. From Lisa's perspective, she's chatting with the supervisor in Slack.

Limitations

  • One channel only. Currently hardwired to #supervisor. Multi-channel routing (e.g., #annotate → voice annotation agent) is planned but not built.
  • No threading. All messages are flat in the channel. Slack threads are not supported.
  • Outbound polls every 2s. Not real-time — there's up to a 2-second delay on supervisor replies appearing in Slack.
  • No rich formatting. Messages are plain text. Slack block kit / attachments not supported yet.
  • Historical replay on restart. The poller has no persistent cursor — on service restart it may replay recent chatbus messages.

Future

  • Multi-channel routing: #annotate → annotation agent, #notes → mcc-notes
  • Persistent outbound cursor to prevent replay on restart
  • Dedicated bot for Lisa — direct messages to a named bot rather than channel messages
  • Rich message formatting for structured responses (task lists, status cards)
